# Аудит веб-панели skygate (десктоп + мобильный)

Цель: не «посмотреть глазами», а **получить список подтверждённых дефектов с
file:line** и закрыть их контрактами. Каждый пункт ниже — либо команда, либо
проверка, которую можно воспроизвести.

## 0. Что где лежит

| Что | Где |
|---|---|
| Шаблоны | `internal/handlers/templates/**/*.html` (`admin/`, `user/`, общий layout) |
| Стили | `internal/staticfs/static/css/themes.css` (и legacy-копия `static/css/themes.css`) |
| i18n | `internal/i18n/catalog_*.go` (`ruXxx` / `enXxx`), helper в шаблоне — `{{t "key"}}` |
| Контракты | `scripts/check_b*.sh` + `scripts/verify_pre_deploy.sh` (`run_check`) |
| Живая панель | `https://<PUBLIC_HOST>/` (admin-сессия нужна для `/admin/*`) |

## 1. Локализация: паритет по КЛЮЧАМ, а не по количеству

`TestCatalogsParity` проверяет только совпадение наборов ключей. Он **не** ловит:

* английский текст в `ru*`-каталоге (и наоборот);
* ключ, которого нет ни в одном каталоге (страница покажет сырой ключ);
* зашитый текст прямо в шаблоне (без `{{t …}}`).

```bash
# (а) ключи, используемые в шаблонах, но отсутствующие в каталогах
grep -rhoE '\{\{\s*t\s+"[^"]+"' internal/handlers/templates | sed -E 's/.*"([^"]+)"/\1/' | sort -u > /tmp/used.txt
grep -rhoE '"[a-z0-9_.]+":' internal/i18n/catalog_*.go | tr -d '":' | sort -u > /tmp/defined.txt
comm -23 /tmp/used.txt /tmp/defined.txt

# (б) RU-значения без кириллицы (не переведено)
grep -nE '^\s*"[a-z0-9_.]+":\s*"[^"]*"' internal/i18n/catalog_*.go | grep -v '[А-Яа-яЁё]' | head -40

# (в) зашитый текст в шаблонах (кандидаты на ключ)
grep -rnE '>[[:space:]]*[A-Z][a-z]+ [a-z]+' internal/handlers/templates --include='*.html' | grep -v '{{' | head -40
```

Правило проекта: **i18n-ключи идут парами RU+EN** (AGENTS §1.10). Новый ключ —
это две строки в двух каталогах + использование в шаблоне.

## 2. Таблицы и мобильный скролл

В `themes.css` уже есть `.table-wrap{overflow-x:auto}`. Таблица **вне**
обёртки уезжает за экран (широкие `code`/UUID/JSON-ячейки).

```bash
# таблицы и их обёртки: сначала список файлов с <table>
grep -rn '<table' internal/handlers/templates --include='*.html' | head -40
# таблица внутри table-wrap?
grep -rn -B2 '<table' internal/handlers/templates --include='*.html' | grep -c 'table-wrap'
```

Проверка в браузере (обязательна для мобильного):
1. Открыть страницу, `Ctrl+Shift+M` (device toolbar), ширина **360–390 px**.
2. Критерии: нет горизонтального скролла **страницы**; скроллится только
   контейнер таблицы; заголовки не «съезжают»; селекты и кнопки не
   выходят за карточку; лонг-текст (ключи, URL) переносится или скроллится
   внутри ячейки.
3. Повторить для/`/my/*` под обычным пользователем (admin-сессия видит
   другие страницы).

## 3. Формы и выпадающие списки

* у каждого `select`/`input` есть видимый `<label>` или `<th>`-подпись;
* `select` не пустой: если список зависит от headscale/БД, при пустом
  источнике должно быть видимое объяснение, а не пустой бокс;
* длинные значения в `option` не растягивают карточку (проверить на 360 px);
* форма с >4 полями переносится (`flex-wrap`/`grid`), а не сжимается;
* кнопки/чекбоксы ≥ 40 px по высоте (тап-таргет), см. `.btn` в `themes.css`.

## 4. Что проверять на каждой странице (чек-лист)

- [ ] страница открывается без 500 и без «сырых» i18n-ключей в тексте;
- [ ] заголовок/подзаголовок/кнопки переведены (RU);
- [ ] таблицы: обёртка `.table-wrap`, скролл внутри, не за экран;
- [ ] формы: подписи, плейсхолдеры, кнопки — переведены и выровнены;
- [ ] селекты заполнены или объяснено, почему пусты;
- [ ] состояние (успех/ошибка) показывается баннером, а не голым текстом;
- [ ] мобильная ширина 360–390 px: нет горизонтального скролла страницы;
- [ ] пустое состояние: «нет данных» + что сделать, а не пустая таблица;
- [ ] длинные значения (ключи, UUID, URL, JSON) не ломают вёрстку.

## 5. Шаблон отчёта

```markdown
| страница | элемент | дефект | file:line | исправление |
|---|---|---|---|---|
| /admin/oidc | баннер «disabled» | не сказано, ЧТО положить в env | templates/admin/oidc_settings.html:12 | ключ oidc.disabled_warn + пример блока |
| /admin/derp | таблица relays | без .table-wrap, 9 колонок | templates/admin/derp.html:210 | обернуть в .table-wrap |
```

## 6. Мобильный каркас (что уже есть)

`themes.css` содержит `@media` для сайдбара (drawer + гамбургер) и
`.table-wrap`. Прежде чем писать новые правила — прочитать существующие
`@media`-блоки и дополнять их, а не дублировать.

## 7. Контракты (обязательно для UI-правки)

Любая правка UI должна оставить гейт зелёным и, если правило новое,
получить свой контракт в `scripts/check_bNNN_*.sh` + `run_check`
в `scripts/verify_pre_deploy.sh` (AGENTS §1.2). Референсы:

* `scripts/check_b322_gate_can_fail.sh` — как выглядит поведенческий
  контракт каталога;
* `scripts/check_b314_*.sh` (группировка навигации) — пример контракта
  на структуру шаблонов;
* `internal/i18n/` — `TestCatalogsParity` (пары RU+EN).
