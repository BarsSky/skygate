# Оформление сообщений skygate-бота

Цель: сообщение **доходит** (его не отверг Telegram) и **читается** (структура, язык,
бюджет). Ниже — правила с реальными причинами; каждое было оплачено в B389.

## 0. Проверка боем, а не чтением кода

Хост `api.telegram.org` **не видит вообще**: `curl` → `000` (таймаут), имена релеев с
хоста не резолвятся. Работает только путь **изнутри контейнера** (B356.1 — релейный
туннель). Токен лежит в БД, а не в `.env`.

```bash
# токен и привязанный чат — из БД, не печатать токен
CT=$(docker ps --format '{{.Names}}' | grep -i '^skygate' | head -1)
TOKEN=$(docker exec skygate-pg-local psql -U admin -d skygate_staging -tAc \
  "SELECT value FROM global_settings WHERE key='telegram.bot_token'" | tr -d '\r\n ')
CHAT=$(docker exec skygate-pg-local psql -U admin -d skygate_staging -tAc \
  "SELECT chat_id FROM telegram_bindings ORDER BY chat_id LIMIT 1" | tr -d '\r\n ')
# вызов всегда изнутри контейнера; в python3 есть urllib, в образе есть wget
docker exec "$CT" python3 - <<'PY'
import json, urllib.request
# ... POST https://api.telegram.org/bot<TOKEN>/sendRichMessage
PY
```

Два приёма, которые экономят чат оператора:

* **запрос-детектор**: положить в конец блока заведомо неверный элемент — запрос
  упадёт целиком, сообщение не отправится, а текст ошибки назовёт первое
  неподдерживаемое место. Так схема выясняется, не засоряя чат;
* **один запрос вместо N**: собрать все кандидаты в одно сообщение; при отказе
  выкинуть названный тег и повторить. Доставляется ровно одно сообщение — успешное.

## 1. Как отправить богатое сообщение

Конверт — **обязательно** вложенный, иначе Telegram молча игнорирует поле и отвечает
`400 rich message must be non-empty`:

```json
{"chat_id": N, "rich_message": {"html": "<h2>Заголовок</h2><p>текст</p>"}}
```

* `reply_markup` (инлайн-клавиатура) кладётся **рядом** с `rich_message` — работает.
* Блоки `blocks` имеют **другое** имя типов, чем ожидает skygate
  (`heading`+`size`, `table`+`cells`, `list` из объектов; `section_heading` и
  `aside` не существуют). В skygate на провод идёт HTML — используй IR и
  `renderBlocksAsRichHTML`, не собирай JSON блоков руками.
* Принятый словарь (проверен целиком): `h1`–`h6`, `p`, `b`, `i`, `u`, `s`, `code`,
  `pre`, `a`, `br`, `hr`, `blockquote` (+`expandable`), `ul`/`ol`/`li`,
  `details`/`summary`, `footer`, `table bordered striped` (+`caption`, `th`),
  `tg-spoiler`, `mark`, `sub`, `sup`, `tg-time`, `input type=checkbox`, `divider`.
* Плоский фолбэк (`sendMessage`, `parse_mode=HTML`) знает **только**
  `b/i/u/s/code/pre/a/span/blockquote/tg-spoiler` — rich-only тег там даёт 400 и
  теряет сообщение. Один IR, два рендерера.

## 2. Скелет сообщения

```
<h2>🛰️ relay mow — degraded</h2>            ← объект + состояние, глиф важности первым
<table bordered striped>                      ← факты, 2 колонки, до 8 строк
  <tr><th>Поле</th><th>Значение</th></tr>
  <tr><td>Маршрут</td><td>0.0.0.0/0 не одобрен</td></tr>
</table>
<blockquote>Что это значит одной фразой.</blockquote>
<details><summary>Подробности</summary>…</details>   ← длинный дамп, по тапу
<footer>skygate v1.5.130 · 2026-10-16 12:00 UTC</footer>
```

Глифы: 🚨 авария · ❌ отказ · ⚠️ предупреждение · ✅ восстановление/успех ·
ℹ️ справка. Бюджет: **≤16 блоков** и **~3000 знаков** на push; тело
`sendMessage` — жёсткий предел **4096 code points** (не байт!).

## 3. Экранирование: значение хранит логический текст

Каталог **не** содержит `&lt;`/`&gt;`/`&amp;`. Пиши `<username>`, `<b>жирный</b>` —
экранирует граница отправки (`sanitizeTelegramHTML`, вызывается в `sendPlain` /
`editMessageText` при `parse_mode=HTML`):

* тег из словаря проходит с атрибутами;
* любое другое `<слово>` → `&lt;слово&gt;` (иначе 400 и **команда пропадает
  молча** — так были мертвы `/invite`, `/accept`, `/mesh create`, `/mesh join`);
* несбалансированный тег экранируется (обрезанное тело — источник);
* голый `&` → `&amp;`; существующие сущности не трогаются (идемпотентно).

Если делаешь ветку с `markHTMLReply()`, помни: он ставит `parse_mode=HTML` на
**всю** функцию, включая подсказку об использовании — её плейсхолдеры тоже
пойдут в HTML.

## 4. Данные: не показывай ноль вместо ошибки

Класс, который повторялся в skygate трижды (`/status` — правильно, `/my_status` и
`/exit_nodes` — нет):

* ошибка чтения → **именованное состояние**, а не `0`/`offline`/пустой список.
  `derr != nil` **не** значит «у пользователя ноль устройств»;
* проверяй, что источник вообще **кто-то заполняет** (таблица `devices` не имела
  писателя — и все exit-узлы годами рисовались `offline`);
* значения, которые выглядят как факт (`v0.32` в `/version`), должны читаться
  оттуда, где факт лежит, либо отсутствовать;
* успех операции («ACL пере-применён», «сообщение отправлено») подтверждай
  результатом вызова, а не фактом его попытки.

## 5. Язык и числа

* Любая строка — ключ в **обоих** каталогах (`catalog_bot.go` RU+EN). `grep -c '%'`
  в RU и EN должен совпадать: `TestPlaceholderOrder` сверяет **количество**
  плейсхолдеров, но **не** количество аргументов на вызове — `%!s(MISSING)`
  проскочил именно так.
* Не бери format-ключ (`"правил: %d"`) как подпись таблицы — напечатается сырое
  `%d`. Для подписей есть label-ключи.
* Длину считай в **рунах** (`len([]rune(s))`), не в байтах: байтовая обрезка рвёт
  кириллицу посередине и Telegram отвергает сообщение целиком. Маркер обрезки —
  на языке чата.
* Обрезка не должна попадать внутрь тега/сущности (`trimToTagBoundary`).
* Никакого Markdown в plain-тексте (`*жирный*`, бэктики, ``` ```): он показывается
  символами. Либо HTML, либо чистый текст.
* Никакого зашитого английского: статусы, «ago»-суффиксы, `[no limit]`,
  заголовки колонок — тоже ключи.

## 6. Уведомления (алерты)

Идут через `SendAlert` → `postToChat` (без parse_mode, с markdown-забором из
бэктиков — это тоже дефект). Для нового алерта:

1. текст — из i18n, не `fmt.Sprintf` в месте вызова;
2. важность → глиф, объект → заголовок, детали → `<details>`;
3. дедуп: алерт на **переход** состояния, а не на каждое срабатывание;
4. неудачная доставка должна быть видна (сейчас `SendAlert` возвращает 0 и на
   ошибке чтения таргета, и на «не настроено» — их надо различать).

## 7. Чек-лист перед коммитом

- [ ] Полезная нагрузка — `rich_message.html` (не `blocks` верхнего уровня).
- [ ] Клавиатура, если есть, передана в `SendRich` (иначе пропадёт при фолбэке).
- [ ] Ни одного сырого `<placeholder>` в HTML-ветке и ни одного `&lt;` в каталоге.
- [ ] Ключи есть в RU и EN; на языке чата и подписи, и маркеры.
- [ ] Ошибка чтения не превращается в `0`/`offline`/«пусто».
- [ ] `go test ./internal/telegram/ ./internal/i18n/` зелёный.
- [ ] Контракт: `bash scripts/check_b389_rich_message_wire.sh`.
