## Recurring traps — skim before touching anything

- `docker compose` interpolation is **CWD-relative**: with `-f /abs/path.yml` from elsewhere the project `.env` never loads and `${VAR:-default}` silently wins. Always `cd <project dir>` or pass `--env-file`; `docker compose config` can render correctly while `up -d` uses the default.
- `restart <svc>` keeps the old container definition — new `extra_hosts`, volumes and `secrets:` need `up -d --force-recreate --no-deps <svc>`.
- Source-only changes need **no** image build (the entrypoint compiles from the bind-mounted repo); `docker compose build` is only for Dockerfile changes.
- **Three operator-managed files must survive every pull/reset:** `docker-compose.yml` (the operator's `extra_hosts` + host hostname), `go.mod`, `go.sum`. `git status` on the VM before any `git reset`/`git checkout`; never `git clean -fd` there.
- Never commit a private LAN IP, a real internal hostname, a credential or a key — use `<VM_HOST>`, `<PUBLIC_HOST>`, `example.com`, RFC 5737 addresses. `.githooks/pre-commit` rejects the known leak patterns in the staged diff.
- `git push` runs `.githooks/pre-push` → the whole gate (10+ min on Windows/git-bash); `--no-verify` is for prod emergencies only. A crashed unit needs `systemctl reset-failed <unit>`.
- `.gitignore` negations are order-sensitive and the **last match wins**: `!scripts/check_*.sh` is overridden by a later `check_*.sh`, so new check scripts stay untracked without `git add -f`.
- Two migration chains (PG + SQLite): extend both in one change. `ADD COLUMN IF NOT EXISTS` is invalid SQLite; `?` is fatal for pgx; `length()` counts bytes vs characters.
- Add columns only via `addColumnIfMissingSQLite(d, table, column, ddl)` — `ddl` must be the **full definition including the column name** (it emits `ALTER TABLE <t> ADD COLUMN <ddl>`).
- Never swallow `ALTER` errors as "already applied": that silently removed three columns from fresh databases and made SQLite un-bootable on the second start.
- After loading a `sqlite3 .dump` into PG, set every primary-key sequence to `MAX(id)+1`. The PG **primary is not on `localhost`** (that port is a read-only replica; writes succeed and do nothing). SQLite `PRAGMA foreign_keys` is **per connection**.
- Scope firewall rules to the traffic, not the source host: a `/32` DROP for a noisy orphan client also killed the legitimate reverse proxy and froze `last_seen` for every device.
- `INSERT OR IGNORE` never re-attributes existing rows — use `UPDATE`. A tag in `tagOwners` does not mean a node carries it, and an unwhitelisted tag is rejected on first sight.
- Add a new tag **before** removing the old one. headscale 0.29 rejects uppercase tags, which skygate sees only as "pending forever".
- `tailscale up` on an authenticated node is a no-op; re-auth is `tailscale up --force-reauth --reset`, and a tag change belongs in `headscale nodes tag --force`.
- `--advertise-routes` **replaces** the list. Never advertise the subnet the host is inside, the bridge CIDRs, or `0.0.0.0/0`.
- Never ship a reconciler with a dry-run default: a `false` that logs what it would have done reads as working while changing nothing.
- Never edit Go/templates with line-index shell tricks (`sed -i`, `$lines[618]=…`) — a line-range rewrite already deleted a `return` and a closing brace. Move a handler's tests in the **same commit** as the handler.
- Go `html/template` rebinds `.` inside `range`, so `{{if eq $ar.ID .ID}}` in a nested range is always true — compute in Go. Annotating a struct **after** copying it into a slice/map loses the annotation. A missing template key renders `<no value>` and nothing fails.
- New handlers go to `internal/feature/<name>/`, never back into `internal/handlers/`. A check that needs live state (docker daemon, DB, VM) must report **SKIP, never FAIL**.

## 1. Deployment & containment

**L-01 — Container DNS is the host's DNS, and `127.0.0.1` in a container is the container itself.** The host resolver mapped the public relay name to loopback and Docker passed that resolver in, so the probe hit its own empty loopback and the UI showed "DERP socket: closed" while the relay was healthy. Fix: pin the name in `extra_hosts` with a value from `.env` (`SKYGATE_DERP_PROBE_HOST`, gitignored) and a harmless loopback default; the same mapping lets the relay certificate (CN = public name) verify inside the container. Guard: contract K of `scripts/check_b260_derp_status_collection.sh` reads the compose file. (B260)

**L-02 — A deploy that "succeeded" can run the old network config.** `docker compose config` rendered the right value and the deploy reported success, yet the container still had old `extra_hosts` — the command ran from the wrong CWD (so `.env` never loaded) and a plain `restart` kept the old definition. Guard: `scripts/rebuild_deploy.sh` step 2.5 warns when the probe host is unset, and `CHECK_B260_STRICT=1` makes it fatal. (B260)

**L-03 — Credential and IP leakage is a recurring, caught-late class.** A live admin password and the SSH host shipped to a public repository as **default fallback values** in `scripts/verify_login.sh` (v0.33.1.42, cleaned in v0.34.0.1). Guard: `.githooks/pre-commit` blocks the old password, the default DB password, the private-IP literal and the `user@<private-ip>` form; the convention is `<VM_HOST>` plus RFC 5737 addresses ([`INSTALL.md`](INSTALL.md)).

**L-04 — The live host can carry two installations and nothing warns you.** A dead native systemd+SQLite install coexisted with the working docker+PG one, showing `active (activating) (auto-restart), restart counter is at 98779` and a 493 MB / 212,742-line journal, and its earlier `config: HEADSCALE_API_KEY is required` failure **masked** the SQLite open bug (L-14) for weeks. Run `systemctl disable --now skygate` for the unused install kind before diagnosing DB problems.

## 2. Docker & Compose

**L-05 — `restart` is not `up --force-recreate`.** A plain restart reuses the container definition, so new `extra_hosts`, bind mounts and `secrets:` never apply and a freshly built binary runs with the old `/etc/hosts`. Use `stop` + `up -d --force-recreate --no-deps <svc>`.

**L-06 — Know what is actually in the image.** The headplane image is distroless (no `sh`/`wget`/`curl`), so a `test: wget …` healthcheck fails forever and the container is permanently unhealthy. The skygate image has no `sqlite3` (use a throwaway `alpine:3.20` for `.recover`/`.dump`) and its busybox `wget` has **no cookie support**, so cookie-authenticated admin POSTs from inside the container need a real HTTP client. (v0.32.16)

**L-07 — Never mount a secrets file unconditionally.** With an empty auth-key file, `tailscale up --authkey=` blocked reading stdin forever and hung the entrypoint; a literal auth-key env var plus a bind mount also shadowed paths. Gate the daemon on a non-empty key path *and* gate the `secrets:` mount. (v0.32.8/11/15)

**L-08 — Graceful shutdown needs an explicit contract, and a one-connection pool deadlocks.** `stop_grace_period: 30s` plus a `/healthz` healthcheck is what lets Go's `db.Close()` flush the SQLite WAL before Docker escalates to SIGKILL (it covers the deploy-time-SIGKILL class only, not a full disk). Separately, `SetMaxOpenConns(1)` with `synchronous=FULL`, adopted as corruption insurance, caused a CASCADE-LOCK hang under load; the fix is `MaxOpenConns(15)` / `synchronous=NORMAL` / `busy_timeout=2s` — the durability setting was a red herring that also cost throughput. (B31, v0.32.14)

**L-09 — Prefer an embed over an image-layout dependency.** Templates were embedded but `static/` was read from disk while the prebuilt Dockerfile copies only the binary + entrypoint, so the panel rendered unstyled — no CSS, system fonts, no icons, dead dark theme, missing webfonts — and dev never saw it because the bind mount hid the gap. Fix: `//go:embed static` plus `http.ServeFileFS`, keeping the cache-header policy and traversal guard bit-identical. Guard: `scripts/check_b_mod_static_embed.sh`.

## 3. systemd, service lifecycle & native installs

**L-10 — A service cannot restart itself, and its children die with its cgroup.** On a native install the unit runs skygate unprivileged under `ProtectSystem=strict`: it cannot write the binary or run `systemctl restart skygate` (`sudo -n true` → "a password is required"), and a `setsid` child is killed with the cgroup — privilege, not missing code, blocked the native auto-updater. Fix (B261) keeps the model: the service writes **data only** (`<data_dir>/update/request.props` — job id, target tag, previous build, pid; no paths), a root-owned path unit fires a root-owned service, and a root-owned applier does backup → download → SHA256 → migrate → swap → restart → healthz → rollback. The applier never `source`s the request file (that would turn an app compromise into a root shell); every path comes from a root-owned config, and the env file is parsed as data and passed through `env(1)`.

**L-11 — You cannot `install` over a running binary, and a `0700` work dir blocks the service user.** A write onto a live executable fails with `ETXTBSY`, so the applier writes a new file and does an **atomic rename**, keeping `skygate.prev`. `mktemp -d` creates the work directory `0700` root-owned, which made the migration step fail with `env: …/apply.XXXXXX/skygate: Permission denied`; it needs `chmod 0755`, safe because the contents are checksum-verified. (B261.3)

**L-12 — "Up" is not "the right build".** Accepting HTTP 200 on `/healthz` accepts a binary that boots and reports another build; poll for the **build string of the target tag**, and on mismatch restore `skygate.prev`, restart, verify, report `rolled_back`. The live canary produced `verdict: done` (build matched in 2 s) and, for a wrong-build artifact that boots, `verdict: rolled_back` with the binary restored byte-for-byte — without the check the update would have reported success while a foreign binary served the port. (B261)

**L-13 — A flag that was never a flag.** `--migrate-only` does not exist; it is the **subcommand** `migrate-only` (`cmd/skygate/main.go`). The wrong form was in the applier *and* in both manual-step lists in `internal/update/manual.go`, so the documented fallback was broken too. (B261.4)

**L-14 — `SKYGATE_DB=sqlite:/path` never opened; every native SQLite install was dead on arrival (B261.1).** Banner printed, no listener, systemd restart loop, and a foreground run eventually showed `db: unreachable after retries: 5 attempts: dialect open "sqlite:/var/lib/skygate/skygate.db": … unable to open database file: out of memory (14)`. `openSQLite` converted only *bare* paths to the driver's `file:` form and skipped `sqlite:` DSNs — a scheme that driver does not know — so SQLite tried to create a **relative file literally named `sqlite:/var/…`**, failed `SQLITE_CANTOPEN` (14), and the driver reported it as OOM. That is exactly the form the installer writes; it was missed because every SQLite test used `:memory:` and the two `sqlite:/…` tests asserted only dialect classification. Fix: strip the prefix centrally plus real file-open tests for all three accepted shapes.

**L-15 — Detection order and the install-kind enum are contracts.** Container markers must be checked **before** `/run/systemd/system`: skygate runs in a container *on* a systemd host, so a permissively bind-mounted `/run` made detection report the systemd kind and the update page printed `systemctl restart skygate` for a container with no such unit. The install-kind enum is rendered as a string into state and audit, so new kinds are **appended** and ordinals must not move; OpenRC was missing entirely, so every Alpine install detected as unknown and `/admin/update` refused, printing the Docker procedure. The OpenRC path needs `rc-service restart` with a `start` fallback, a sudoers trigger (no systemd path unit), and the install-kind/state env vars in `/etc/conf.d/skygate`. (B262)

**L-16 — Native state paths and installer surfaces.** The container-default update-state path does not exist on a native host, so every state write was a **silent no-op** until the installers exported it. Changing an installer default means changing three surfaces (the env-file heredoc, the per-OS installer flag, and the wrapper's exported allow-list), and a flag present in only two silently lost the feature; a clean Debian 12 host also revealed the dependency lists omit `xxd`, so the env-file writer died and `set -euo pipefail` aborted the install **between** installing the binary and writing the env file, unit and helper — a binary and no service, after a success line. Fix: `openssl rand -hex 32` → `od -An -tx1` → `xxd` last.

**L-17 — One-time migrations need an idempotent script with a preserved rollback path.** The derper-in-docker migration script is ordered and re-runnable: pre-flight (systemd daemon active, certs at the canonical path, docker up) → build image → stop+disable the systemd unit and render the compose template → start the container → verify (`:443` listening, STUN `:3478` listening, HTTPS `GET /` = 200). Downtime is ~3–10 s while the port changes owner, and the systemd unit is left in place (only stopped/disabled) until the operator confirms stability — deleting it early removes the rollback.

## 4. Database: PostgreSQL / SQLite parity & migrations

See also [`db-schema.md`](db-schema.md), [`backup-restore-and-migration.md`](backup-restore-and-migration.md), [`disaster-recovery.md`](disaster-recovery.md).

**L-18 — SQLite drops writes silently when the disk is full; this is the root cause of the recurring corruption incidents.** `sqlite3_step()` returned `SQLITE_OK` while no bytes reached disk, so the btree went inconsistent and the process kept running — per-tick inserts "succeeded" and were lost, with no error log — while `PRAGMA integrity_check` reported `Tree 12 page 7838 cell 334: 2nd reference to page 9775`, `Rowid 120378 out of order`, `database disk image is malformed (11)`. The disk had hit 100% (containerd's snapshotter held 6.7 GB of un-GC'd layers plus 916 MB of journal; why it grew without GC was never determined). Guards: R30 runs `integrity_check` on a copy of the live DB, and R31 hard-FAILs at ≥85% disk usage because of this exact mode. (v0.32.5)

**L-19 — `DROP`+`CREATE` is not corruption recovery.** Corrupted pages stay on the freelist, so rebuilt tables reuse them and `integrity_check` fails on the **same page numbers** forever. Use `sqlite3 .recover` into a SQL dump inside a throwaway `alpine:3.20` container, filter the `sqlite_sequence` statement, rebuild, `integrity_check`, `chown 1000:1000`, swap the file into the volume, restart, re-apply the ACL — the recovery returned **more** rows than before, because data had been hiding in corrupted free pages.

**L-20 — All SQLite DDL goes through one chokepoint, and the `ALTER` helper needs the column name twice.** `execSQLiteDDL(d, stmts)` (`internal/db/sqlite_ddl.go`) recognizes `ALTER TABLE … ADD COLUMN …` and rebuilds the statement itself, so the helper `addColumnIfMissingSQLite(d *sql.DB, table, column, ddl string)` emits `ALTER TABLE <table> ADD COLUMN <ddl>`. Pass only a type rather than the **full definition including the column name** (`ssh_port TEXT NOT NULL DEFAULT ''`) and a rerun fails with `duplicate column name`; table and column names are interpolated (`PRAGMA table_info` takes no bound parameters), so callers pass hardcoded literals.

**L-21 — Swallowing DDL errors as "already applied" hid two defects, one of which makes a release unusable.** The old migrations ran ~18 loops shaped `if _, err := d.Exec(q); err != nil { continue }`; statements used PostgreSQL's `ADD COLUMN IF NOT EXISTS` — a **syntax error in SQLite** — and the error was read as "column exists", so `exit_servers.{ssh_target,ssh_key_path,accept_routes}` and `device_rules.device_ip` never appeared on a fresh database (found by running the chain on a real database, not by reading it). Fix: `PRAGMA table_info`-based idempotency plus returning every other statement's error. Separately ~10 unprotected `ADD COLUMN` statements return `duplicate column name`, and because migrations run on every open the error propagates through the open-ping, so a SQLite deployment could not boot a **second** time: `v44 add user_name: duplicate column name` (fresh **or** existing DB) means **v1.5.8 cannot run on SQLite at all**, a native SQLite host needs v1.5.9+, and the applier's pre-swap migrate step is what keeps a failed attempt from bricking the host.

**L-22 — The dialects differ structurally, not cosmetically.** `?` → `$1,$2,…` (`$N` is accepted by SQLite, but `?` is fatal for pgx); `INSERT OR IGNORE` → `ON CONFLICT … DO NOTHING`; `INSERT OR REPLACE` → `ON CONFLICT (col) DO UPDATE SET …`; `datetime('now')` → `now()`; `strftime('%s',col)` → `EXTRACT(EPOCH FROM col)::bigint`; `IFNULL` → `COALESCE`; `json_extract(col,'$.f')` → `col->>'f'`; `GROUP_CONCAT` → `string_agg`; `INTEGER PRIMARY KEY AUTOINCREMENT` → `BIGSERIAL`; `BLOB` → `BYTEA`; `DATETIME` → `TIMESTAMP WITH TIME ZONE`; `TEXT[]` → `TEXT`; `VARCHAR(N)` → `TEXT`; `'t'/'f'` → `true/false`. `PRAGMA` statements are SQLite-only, both chains must grow together (49 SQLite migration functions exist only because a script reverse-ported the PG ones), and `ON CONFLICT … DO UPDATE` / `RETURNING id` / `LastInsertId()` work on both.

**L-23 — Portability is one-way, and a stale comment hid it.** PG can emulate SQLite (there is even a PG `strftime` shim), never the reverse — yet one file unconditionally returned the PG timestamp expression with the comment "as of v1.3.0 skygate is PG-only; the SQLite variant has been removed" after v1.5.4 restored SQLite, so ~12 call sites emitted `EXTRACT(EPOCH FROM now())::bigint` into SQLite (`SQL logic error: near "FROM": syntax error`). Other live leaks: a shared `tagged_at` expression (SQLite), `node_owner_map.go:806-809` `?`+`strftime` (PG, error swallowed → exit-node auto-detect silently dead), the version monitor's `LIMIT ?` (PG, swallowed → release history permanently empty), `mesh/cleanup.go` `ANY($1::bigint[])` (SQLite). Fix: one dialect source of truth, a leak-guard test, and runtime tests that **execute** queries on real `:memory:` SQLite.

**L-24 — Two DB open paths left every CLI verb dead on SQLite.** The web path routes through the dialect-aware opener, but a second opener is hard-wired to the pgx driver and is used by the CLI subcommands, so `skygate init|cluster|migrate|acl-apply|derp-probe|regapi-credentials` do not work on SQLite at all; guard by grep that only one file calls that driver. Coverage debt in the same area: ~50 test files still skip themselves with a "v1.3.0: SQLite" reason, leaving whole packages untested.

**L-25 — Migration metadata drifts between the chains.** The PG chain ended at V071 while the SQLite chain stopped at V070 and its migration function **did not exist at all**, so the cert-sync table was never created on SQLite and DERP cert auto-renew was dead there; a driver map also labelled a version with a filename that does not exist. Rule: one migration = one PR containing the PG **and** SQLite function, both registry entries, and a green schema-parity test (version-set equality, per-table column-set equality, chain-run-twice idempotency, PG→SQLite→PG round trip).

**L-26 — PG-specific migration protocol.** Wrap every migration in one transaction (several auto-committing statements leave PG permanently inconsistent, and a suspended migration holds locks), and remember `ALTER TABLE … ADD COLUMN` takes **ACCESS EXCLUSIVE**: use `IF NOT EXISTS` with a constant default, or expand-contract for non-constant defaults (nullable → batched backfill → `SET NOT NULL` in a later release), with `CREATE INDEX CONCURRENTLY … IF NOT EXISTS` for indexes. Destructive statements are forbidden in the auto path, gated behind an env flag plus an explicit click, because the **old binary is still serving** and would crash on its next request; `SET LOCAL lock_timeout = '10s'` makes a blocked migration fail fast instead of hanging the instance. Helpers live in `internal/db/pgmigrate/`; catalog rows B11 (no destructive DDL), B12 (per-driver SQL form), B18 (PG build), R26 (live lock_timeout), R27 (live PG tests).

**L-27 — The schema-conversion tool is a silent data-loss vector.** It rewrites DDL with string replacements and copies with `SELECT *`, so run against an incomplete SQLite schema the missing columns (`ssh_target`, `ssh_key_path`, `accept_routes`, `device_ip`) arrive empty — silently destroying exit-node configuration and per-device IP rules. Required: a pre-flight column-parity check that **refuses** and lists the lost columns, a mandatory source backup, post-checks on row counts and checksums, and a round-trip test in CI; read schema from `INFORMATION_SCHEMA` (PG) vs `sqlite_master` (SQLite) and topo-sort by foreign key.

**L-28 — Sequences, cutover order, and the rollback ladder.** After a dump load every sequence still starts at 1 and the next insert fails with `duplicate key`, so the order is: dump → rewrite SQL → create a fresh PG DB → run the migrations in order → load the data → verify row counts for **every** table → set every primary-key sequence to `MAX(id)+1`. Rollback ladder in order: flip the DNS record back (bounded by the 5-minute TTL) → `git revert` the migration commits (main stays on the old backend) → restore the pre-migration dump (kept 30 days) → rebuild the old host from backup artifacts; tolerance stops being clean once skygate has started twice on the new DSN, because the audit log and ACL snapshots diverge.

**L-29 — DSN selection, the primary's real address, and WAL hygiene.** `SKYGATE_DB` is the unified selector (`sqlite:/path` or `postgres://…`, classified by `db.DetectDSN`); the older DSN variable is still honoured when it is unset, and a live host carried a stale value on an old bridge address while the new one was correct — while unset `SKYGATE_DB` silently falls back to local SQLite unless the require flag is set, and commenting out the PG DSN with the SQLite compose file crash-loops with `unknown DSN format`. The PG **primary is reached over the docker bridge** (the `localhost` port is a read-only replica, so writes there succeed and do nothing), a failing WAL push piles WAL until the disk fills (monitor both), and restore expects Patroni stopped first with the data dir recreated, a backup fetched, and `recovery.signal` written before PG starts. The archive command must **source one env file** because `envdir` wants a directory and is often absent, and only the bucket-prefix variable gained the `WALG_` prefix — prefixed endpoint/credential names make object stores answer `InvalidAccessKeyId: 403`.

## 5. Networking: headscale, DERP, ACL/tags, tailnet, DNS, firewall

See also [`networking.md`](networking.md), [`derp.md`](derp.md), [`acl-rules-reference.md`](acl-rules-reference.md), [`troubleshooting.md`](troubleshooting.md).

**L-30 — `approve-routes` never worked because the headscale config template omitted `unix_socket`.** `approve-routes: exit status 1: Error: connecting to headscale: connecting to /var/run/headscale/headscale.sock: context deadline exceeded` appeared 144 times in 6 hours — the whole "approved half" of the route pipeline was dead, and it reproduces **inside the headscale container**, so it was never a skygate bug. The config declared a gRPC listen address but no `unix_socket`, so the server never created the socket while the CLI (which has **no** socket flag, only a config flag) always defaults to that path; fix by declaring `unix_socket` + `unix_socket_permission: "0770"` in both the config template and the bootstrap script and restarting headscale (~5–10 s, sessions survive). **Masking trap:** automatic route approval produced a green `advertised_routes_ok` while skygate's own approve calls failed 144 times — a green metric can come from a different mechanism than the one you are debugging.

**L-31 — An over-broad firewall rule took the whole tailnet offline (B179).** All 14 Tailscale clients **and** the skygate VM showed `online=false` with `last_seen` frozen at the minute a previous deploy inserted `iptables -I DOCKER-USER 1 -s <orphan-client-ip> -p tcp --dport 50444 -j DROP`. That rule, added to silence `node not found` 404 noise, also matched the **legitimate reverse proxy** on the same host, which returned 504 to every client fetching `/key` and pushing `/machine/map`, so no client could ever update `last_seen` again; fix by removing the rules and persisting the corrected set to the iptables rules file. Guard: `scripts/check_b179.sh` (no rule in live iptables, none in the persisted file, headscale answers **401 not 504** on 50444) — it was not a DERP issue, not a preference bug.

**L-32 — headscale's `node not found` 404 stream is noise, and peer identity must be measured.** The signature is `ERR user msg: node not found code=404` with `POST /machine/map … status=404`, a 15-byte body, 0.2–0.5 ms, from a **persistent** source port, in bursts of two every 20–40 s, while the *same host* holds a valid client returning 200 with a 0-byte body in 200–500 ms — headscale is correctly rejecting a stale node key. You cannot filter it by source port (both streams are HTTP/2 with stream multiplexing) and the blunt DROP is exactly what caused L-31, so the options are client-side re-auth or ignore; a 12-day-old runbook misidentified that host as the operator's router when it is the reverse-proxy host (confirmed by the proxy's own admin UI, a host constant in a helper script, and a `ws_admin` label in `classifyDerpPeer`), so classify peers from code constants and fresh probes.

**L-33 — "Tailnet split" was policy isolation, not session divergence (B111).** `tailscale status` inside the container listed 4 nodes while headscale reported 10 online, and the earlier theory ("control-plane session divergence", fix = re-auth every device) was explicitly retracted: the real cause was an incomplete infra-user migration — the infra-node predicate matched only a hostname prefix and one tag, never the exit-node tag; the backfill used `INSERT OR IGNORE`, which adds rows but never **re-attributes** existing user-owned exit-node rows; the generator emitted no catch-all grants; and per-device grant writing silently skips buckets with fewer than 2 devices. Fix: extend the predicate, change `INSERT OR IGNORE` → `UPDATE`, and add the infra exit-node tag helper; the remaining operator step is to re-tag the 5 infra nodes, which costs ~3–5 minutes of downtime each because Tailscale cannot change tags without re-registration. Guards: `scripts/check_b111.sh`, the `tailnet.split_suspected` system test, `scripts/tailnet_probe.sh` — and **do not start with re-auth**.

**L-34 — Advertising the subnet you are already on creates a routing loop (B236).** Latency to a peer grew from ~500 ms to ~1700 ms because the host advertised its own LAN plus the bridge CIDRs, so route-accepting clients installed a more-specific route via the tunnel and bounced traffic through the relay and back over the same LAN (137 ms peer RTT × 3–4 hops), while LAN clients on that subnet lost direct access to siblings because Tailscale shadowed the Ethernet route. Fix: clear the advertisement and restart the daemon, then verify `ip route get <LAN_GW>` reports the Ethernet device — measured after: `ping` 0.6–0.9 ms, TLS `GET /` 4–16 ms. Guard: `scripts/check_b236.sh`.

**L-35 — There is no single "preferred exit node": three layers must all be present.** `device_rules` (intent) → `device_exit_node_prefs` (written by the reconciler) → headscale grants carrying `via:`, and a ~24-hour outage for one site (while other rules worked) came from two causes: the reconciler's live flag defaulted to `false` (dry-run), so the hourly pass correctly computed the change and **silently skipped the write**, and the ACL flag for `via:` was unset, so regenerated grants had no `via:` and the client picked its default exit. Fix: default the reconciler to **live** with an explicit opt-out, enable `via:` emission, and re-apply the ACL (verified after: 213 grants carrying `via:`); guard with a unit test requiring an orphan user id to still produce a CREATE change plus decision-matrix tests. Deliberate non-actions: two exit nodes with no preference = SKIP, and a missing canonical tag because the host vanished from the ownership map = no-op so a returning host is not clobbered.

**L-36 — Route delivery has an ordering trap, a tri-state field, and an injection vector.** The SSH step runs first and the approve step runs **unconditionally** afterwards, so a failed SSH still reports `approved=N` in the UI while route acceptance never reached the node — routes were computed correctly (32 of 147) but not applied. `accept_routes` is `-1/0/+1` where **`0` means "don't touch"**, so the flag is omitted entirely; SSH uses `accept-new` host-key checking with a 10 s connect timeout (first connect 1–3 s, and four relays spaced by the 30 s stagger ≈ 1.5 min per sync), and a relay daemon restart means up to 5 minutes with no exit-node capability. Security: `ssh_target` comes from the database and is appended positionally to the `ssh` argv, so `-oProxyCommand=<cmd>` is parsed as an **option** and executes a command — validate it with a strict regex at the form and again before exec, pass `--` before the host, force `-oProxyCommand=none`, and require an absolute key path.

**L-37 — Skygate could not Tailscale-SSH into its own exit nodes.** The generator emitted an SSH rule source list of `["tag:private", "<admin>@<domain>"]`, but the skygate host carries an infra tag and its traffic arrives as that host (NAT through the bridge to the host daemon), so the tailnet policy refused it with `tailscale: tailnet policy does not permit you to SSH to this node`. Fix: a helper that appends the skygate host's infra tags from ownership data so a rename is picked up on the next regeneration, with a fallback to the legacy two-element list — and remember a hand edit to the live policy is temporary, since any ACL apply overwrites it (the regenerated element order differs from the hand edit, which is how you prove regeneration).

**L-38 — `/admin/derp` must not require `--debug`, and its status collection had three compounding bugs.** Operators run the relay without `--debug` deliberately (the debug endpoints leak client connection info), so `/debug/vars` returns 403, the JSON parse bails and the page claimed `DERPER-SERVICE: stopped`; fix with a WebSocket upgrade probe against the always-on `/derp` endpoint (`101 Switching Protocols` on any functional relay) that runs **last** so debug-enabled deployments keep the rich panels. The collection also had a probe URL hardcoded to an RFC 5737 TEST-NET address (so all six probes silently failed), plain HTTP against a TLS listener (rejected with `Client sent an HTTP request to an HTTPS server`), and a `LIMIT 1` without `ORDER BY` over duplicate bundled-relay rows inserted by direct SQL that bypassed the guard (so the UI flipped between ports on every refresh) — fixed with deterministic ordering, hostname resolution mirroring the port resolver, TLS with SNI and verification skipped **only** for a literal-IP host, and `extra_hosts` for container DNS (L-01). Guard: 11 contracts. (B260, B260.1)

**L-39 — DERP container and certificate traps.** Manual cert mode **forces** `:443` and the HTTP port must be **80** (the old `8443` default was a leftover from the Let's-Encrypt template); an empty `--verify-clients=` value crashes the daemon; the verify check must match the SNI certificate; port resolution must prefer the database over the env var so a stale variable cannot shadow it; the probe URL must not be conflated with the derpmap URL. Build the image locally from the host's existing binary when the registry refuses, on a **glibc** base because the host binary is dynamically linked and musl needs shims that miss symbol versions, keeping host networking for the privileged ports and STUN. A derpmap's short region label is not a hostname (using it made all 28 public regions render degraded with no latency), a certificate must be the **full chain**, a static cert file never renews itself, and the two cert directories must not be confused because the sync writes one path while the daemon reads another; reload for a cert change is SIGHUP, not a restart (which costs a 1–3 s DERP blip). (B235, B260.2.x)

**L-40 — Editing headscale's config file does not change headscale.** A duplicate derpmap URL was removed from the config but headscale was never restarted, so the process kept serving the old in-memory config; the fix is a compose restart (~5 s blip, clients resume). The ACL fallback that writes a policy file and restarts the container is **currently unreachable** because the template sets database policy mode, so a config change or migration silently re-enables it; most headscale operations still hardcode docker incantations and ignore the container-name variable, and the OIDC restart mode is never persisted (`"auto"` is substituted in two places).

**L-41 — headscale duplicate node names behave asymmetrically, and that breaks device attribution (0.29.1).** Client-driven registration auto-bumps the name (`resolveGivenName`, `hscontrol/state/node_store.go:365-388`: `base`, `base-1`, `base-2`, …), so a second device silently becomes `<device>-1` while its client still believes it is `<device>`, whereas an **admin** rename collision is rejected with HTTP **409** `given name already in use by another node` (`setName`, `node_store.go:243-271`); a same-key re-registration preserves the given name and an admin rename is sticky. Hostname ≠ given name — the hostname is client-reported, case-preserved and collidable, while the given name is lowercase, globally unique (not per-user) and is what the dev-tag policy uses — so the ownership map should store the **given name**, since storing the hostname is the root of "pending forever" drift when a manual headscale tag never updates the DB row. Attribution has exactly four strategies (preauth-key id match, temporal window, existing dev-tag, OIDC username match), none of which matches a key minted by the headscale CLI or a node on the synthetic tagged-devices user, and "Sync from headscale" fills **only** the ownership map — it does not create rules, apply dev-tags or mark exit servers.

**L-42 — Tag operations are order- and case-sensitive (B176, B177).** headscale 0.29 rejects uppercase tags with `Error: tag should be lowercase`, which skygate saw only as "pending forever", and without the ACL-side lowercase the policy carries a differently-cased tag and headscale ignores the rule — so lowercase every dev-tag construction site. A tag never whitelisted in `tagOwners` is rejected on first sight with `InvalidArgument: requested tags are invalid or not permitted`, and the original untag-then-tag order therefore destroyed the old tag and left the node with **none**; the correct order is add-first, then untag and the DB row update only inside the success branch. Guards: `scripts/check_b176.sh`, `scripts/check_b177.sh` (10 contracts), live-verified; infra tags belong to the infra owner, the public tag must never be mixed with infra (it leaks the node into the public ACL), and the exit-node tag is required for the catch-all grant.

**L-43 — Device deletion is a multi-table coordinator, not a row delete (B171).** The earlier paths cleaned headscale, the ownership map and the exit-node preferences but left orphan `device_rules` and stale dev-tag ACL references, so the next regeneration either skipped them (policy silently out of sync) or made headscale's policy call return **400**. Fix: one shared coordinator for both scopes — ownership cleanup, preference cleanup, all rules for the device in one query, ACL regen, cache invalidation (otherwise the deletion is invisible for the 5 s TTL) and an audit row; the companion UI bug was a Delete button rendered **inside** an expiry-guarded block, so exit-nodes, subnet-routers and no-expiry devices showed no button at all.

**L-44 — ACL regeneration overwrites; it never merges.** The generator builds a brand-new policy from the rules table and the push replaces headscale's policy wholesale, so a first apply with no rules **wipes every existing grant** — hand-written, UI-managed and operator-reserved grants all disappear, and a mis-ordered rule can create an inter-user leak (both a leak regression and a `via:` regression are pinned by tests). Before any first re-apply on an adopted headscale: dump the live policy, verify the snapshot captured the **live** policy rather than the freshly generated one, and use the import endpoint to convert the existing policy into skygate's shape; there is no merge mode and recovery is the snapshot table.

**L-45 — The Telegram relay uses subnet routes deliberately, not an exit node.** Replacing the default route would push every non-tailnet packet (headscale API, Docker traffic) through the relay, so the relay advertises only the ranges Telegram uses; because that advertisement is static while Telegram adds blocks, a weekly cron resolves the known hostnames through three public resolvers, unions the records, re-applies the routes (whose reset semantics prune stale ranges), prints the approve command, and **refuses** an empty list that would wipe the advertisement and break the bot. Probe-banner semantics: "unreachable" = no approved routes, "unreachable" *with* resolved IPs listed = those IPs fall outside the approved ranges, and "reachable (direct internet)" = skygate egressing locally; the egress selector flashes the real SSH error and does **not** update the stored node on failure. Alerts with no bot configured go to a noop sink, so the audit row is the durable proof. See [`TELEGRAM.md`](TELEGRAM.md).

## 6. Auth / OIDC

See also [`oidc.md`](oidc.md), [`https.md`](https.md).

**L-46 — OIDC is four must-match values, and the redirect URI is an exact string.** The issuer, client id, client secret and redirect URI must match headscale's `oidc:` block value for value — most integration failures are a typo in one of the four — and `redirect_uri` matching is exact per RFC 6749 §3.1.2.3, so a trailing slash, a port difference or http-vs-https is a 400 (`redirect_uri mismatch`) with `Invalid state parameter` or a browser stuck on `/oidc/authorize?` after a *successful* login as the tell. PKCE is S256 only, and clock skew over 5 minutes presents as `invalid_grant`.

**L-47 — Three headscale config traps in the `oidc:` block, and the discovery document is the heartbeat.** The block must be at YAML **top level**, not nested — nesting gives `FATAL no oidc provider configured`, so run `headscale validate` before any restart — and `strip_email_domain` was **removed** in headscale 0.23+, its presence crashing 0.29.x at startup, which is why the generator omits it deliberately; `automatic_authorization: true` is what makes provisioning one-click, while `auto_update: true` re-applies the ACL on **every** login and should stay false in production. Discovery: 404 = the well-known path is not routed, 502 = skygate is down, `jwks_uri returned no keys` = the keypair was not initialized (check the key directory is mounted and writable), and JWKS must return exactly one RS256 key — a `kid` mismatch breaks token parsing and losing the key directory invalidates every issued token. A wrong client secret returns `400 invalid_client` (400, not 401, per RFC 6749 §5.2) and an expired, reused or PKCE-mismatched code returns `400 invalid_grant`; rollback is to comment out the block and restart headscale, the most common cause being a client secret rotated on only one side.

**L-48 — A login round-trip that ignores `next` silently kills the OIDC handshake (B172).** Logging into headscale through its OIDC redirect landed on skygate's welcome page and the device was never registered, because the login handler always redirected to the dashboard and discarded the `next` parameter the handshake depends on. Fix: read, validate and honour `next` through `safeNextRedirect(next, requestHost)` with a hidden `next` input in the form — the validator is an **open-redirect defense** that accepts empty (dashboard), relative, and same-host absolute values, and rejects protocol-relative `//evil.com`, a different host, and non-http(s) schemes (`javascript:`, `data:`, `file:`). Guard: 18 unit tests + 24 contracts.

**L-49 — Fix order matters; two intermediate fixes did nothing (B173 → B173.1 → B174).** The reported chain was: `next` ignored; no visible submit feedback; `HTMLFormElement.submit()` from password managers bypassing `submit` listeners entirely (so a button-only loading state is invisible); and the real defect — OIDC session reading parsed the cookie as a colon-separated string, a format the login handler **never wrote** (it writes an HS256 JWT), so it always returned nil, every authorize call bounced back to login, and the user experienced "the login page keeps resetting my password". Nobody noticed earlier because the hard-coded dashboard redirect meant the broken code was never exercised, so **fixing one bug exposed the other**; the fix delegates to the shared JWT parser plus a user-lookup callback for the email the JWT does not carry, returning nil for a validly signed cookie whose user is gone, with the colon format pinned as REJECTED (22 contracts, 7 subtests). Defense-in-depth: a full-page overlay, a monkey-patched `f.submit` with a short defer so the overlay paints before navigation, navigation listeners, `readOnly` inputs (not `disabled`, so the value still submits), and try/catch so a script error falls through to a normal submit.

**L-50 — A test that uses a test-only header is worse than no test.** The e2e OIDC test passed while the production path was broken because it pre-populated an auth code and set an `X-Test-Session-Cookie-Present` header, bypassing both the real login POST and the real session read. It now deletes the header, issues a real JWT, and asserts the authorize → callback transition, so e2e tests must exercise the production path including the real cookie format.

**L-51 — OIDC-registered nodes need their own attribution strategy, and the public issuer is the fragile part.** An OIDC node has no preauth key and no tags, so the other strategies never fire and the device showed a pending dev-tag forever; the OIDC strategy matches "no preauth key id and headscale user name equals the portal username" with guards against stealing preauth nodes and cross-user ownership, relying on headscale naming the user from the OIDC `name` claim. Two gaps remain: headscale creates a **new** user whenever that claim matches no existing user (so duplicates recur on every fresh bootstrap), and nodes already on the synthetic tagged-devices user with no live dev-tag are skipped entirely. Operator side: the sync page offers six restart modes plus a download-only seventh, a boot flag pushes at boot, and every proxy location must set `X-Forwarded-Proto` (read to render the issuer claim) plus the host headers, with long timeouts because the headscale restart sleeps inside the request — a missing `X-Forwarded-Proto` still redirects to login but with an **empty** `next=`, and a stale env file yields HTTP 200 discovery whose issuer has no scheme. (B167, B168, B175)

## 7. UI / templates / i18n

See also [`features.md`](features.md).

**L-52 — Go template scope and copy semantics caused two consecutive releases of wrong data (B178, B178.1).** All 103 of one user's rules showed the same preferred exit node while the database lookup returned the right value, because an inner `range` over an annotated slice rebinds `.` to the inner item, so the comparison was always true and the value ended as the last row's. Fix: a package-level rule type with the preferred host resolved in Go by a helper that batches one lookup per unique (user, device) — 3 queries instead of 324 — with the template reading the field directly; the follow-up bug was that the annotation ran **after** the grouping loop that copies each rule into the per-node map, so the copies the template iterates had empty fields. Guards: 8 unit tests (including the exact reported case and one asserting a single callback per unique pair) plus a contract pinning the call order by line number.

**L-53 — A `POST` that returns JSON from a plain form is a UI bug (B180).** A per-row "Re-sync" button replaced the page with raw JSON because the handler wrote JSON while the browser followed a normal form POST, whereas the global button was fine because it used `fetch()` plus a manual reload. Fix: redirect to `?ok=…` / `?err=…` and reuse the existing flash mechanism (guard: 5 contracts, live-verified 303 + `Location`); every admin POST ends in a redirect with a flash, and a per-row error must never be routed into the green success alert.

**L-54 — The error surface is architectural.** No shared error-rendering helper exists while `http.Error(...)` is called **482 times in 68 files** (136 with status 500), and `http.Error(w, err.Error(), 500)` both replaces the page with `text/plain` and leaks SQL text, table/column names and sometimes the DSN — `/my/keys` has no flash block at all, so a DB error there can *only* be a raw page, and on SQLite the exit-nodes page became a wall of text because the query read the missing columns (L-21). Fix pattern: never hand `err.Error()` to the user (details go to log + audit, the user gets an i18n key), redirect form POSTs with an error key, **first verify the page renders a flash block** because a redirect without one makes the failure invisible (a regression, not a fix), and never touch `403 forbidden` since redirecting an unauthorized user loops. Guard: a leak-guard test pins a baseline of 101 leaking sites in 37 files that may only decrease.

**L-55 — Silent template/struct mismatches and i18n content bugs both pass their tests.** The registration result page used `{{.PreauthKey}}` while the handler passed `"Key"`, and `{{.OSLabel}}` which **no handler set**, so the page printed an authkey command with `<no value>` and "instructions for `<no value>`" — guard with a test that extracts every template field, subtracts those injected by the layout helper, and fails if the remainder is set by no handler. The i18n parity test proves there are **no missing** keys but cannot see typos, wrong-language values or HTML encoding: seven bot keys ended `&gt;>.` instead of `&gt;.`, eleven used a literal `<ключ>` where Telegram HTML needs `&lt;ключ&gt;` (bypassing the HTML-safety test because four prefixes were missing from `htmlPrefixes`), English values contained Cyrillic, and hardcoded English headers remain in ~14 admin templates with 116 lines of hardcoded Russian in 24 Go files. The refactor's test renderer dumps key/value pairs, so it cannot assert that a page *looks* right — only the VM smoke (166 assertions, RU + EN) covers rendering, and a template changed on a page the smoke does not exercise can pass every unit test while the page is broken.

**L-56 — The UI must never claim a service is running when the state machine has only two branches for three real states (B258.1).** The page showed `tailscaled: stopped` while offering an active "Disable" button, and clicking Start produced `read auth key: open /data/ts/authkey: no such file or directory`, because the third state — configured path, file missing or empty — had been collapsed into "enabled". Fix: an explicit missing-key flag, a 3-way template branch (disabled banner / missing banner plus paste form and hard-disabled Start / normal card), an early refusal in the handler with an actionable message, and 5 tests pinning state exclusivity — enumerate the states before rendering the controls. Related: status pills driven by denormalized rows lag reality, since a killed subnet-router stayed active for 35 s+ because the sidecar's "node disappeared" branch fires only when the node **id** is gone, never when it is merely offline, and the denormalized status is recomputed only on page load.

## 8. Release & self-update

See also [`UPDATE.md`](UPDATE.md), [`deploy.md`](deploy.md).

**L-57 — A multi-arch matrix that pushes the same tag twice leaves the tag broken (Issue #4).** The pre-v1.5.4 release workflow built amd64 and arm64 in separate jobs pushing the **same** tag, so the second push overwrote the first and an older tag answered "no matching manifest for linux/amd64" on amd64 hosts. Decision: the Docker image is **linux/amd64-only**, with ARM operators using the Go tarballs (linux/darwin × amd64/arm64 + windows-amd64) or a local build; re-enabling multi-arch needs one build-push action with both platforms, or two jobs merged with `docker buildx imagetools create` — never two pushes to one tag.

**L-58 — The missing checksum asset was a path collision, and the gate that needed it looked secure.** Releases in that window attached **no checksums**, because the workflow downloaded the artifact into a directory whose only file has the same name, so the file landed one level deeper, and the flatten step then moved the file *into* the same-named directory — the release attached a directory and the uploader shipped nothing; the fix downloads into a differently named directory plus a contract that simulates the workflow's own flatten commands. Meanwhile the applier's hard checksum requirement made native self-update impossible on every real release while appearing to be the secure branch, so it now falls back to the per-asset SHA256 digest from the Releases API and still refuses when neither source exists, with an operator-managed base-URL mirror (checksums mandatory) for air-gapped hosts — a mirror cannot use the API fallback, which is why the asset itself had to be fixed. Two general rules: **verify the artifact, not the job's exit code**, and remember GitHub Actions parses `format()` arguments as literals, so a `| lower` inside `format()` did not apply and produced an invalid mixed-case registry tag path with a failed release and no image. (B261.2, B262, B237.24)

**L-59 — The in-process updater plan was superseded because the blocker was privilege, not design (B261).** The plan's intent survives (poll the Releases API, cache success 6 h and failure 15 min, verify the asset hash before install, SIGTERM with a 30 s grace, `Retry-After: 30` during the update, a failed-update audit row), but the native half shipped as the path-unit design (L-10). Rejected then and still rejected: the heavy GitHub client library (two endpoints vs 100+ dependencies), a migration framework, OS package distribution, in-app release-candidate channels, and unattended auto-update; the rollout that worked was candidate 1 with detection only and the Update button **disabled**, candidate 2 with the bare-binary updater, then the full path.

**L-60 — Installer entry points must not silently ignore flags, and first-run bootstrap must be idempotent.** The readme recommends a compose-file flag the installer does not handle at all, and the per-OS installer has no catch-all branch, so unknown flags are ignored and the operator gets a bare-metal install instead of Docker — every installer path must accept and validate both the DB type and the install kind. First-run adoption of an existing tailnet is deliberately explicit: an hourly cron classifies each portal user's headscale id and **never** auto-deletes a portal user (audit row only), a banner says users were detected but not adopted, the claim-all endpoint claims rows idempotently and case-insensitively (only unclaimed rows or the current admin's), and the exit-server upsert is idempotent by primary key (guard: 12 contracts). Trap: claim matching is case-insensitive, so a case mismatch is a silent no-op — the original root cause of "no device" with no explanation.

## 9. Testing & B-check contracts

See also [`internals.md`](internals.md).

**L-61 — The B-check is the unit of "done", and a missing or mistyped script is a silent no-op.** Every block ships a check script, a row in `scripts/verify_pre_deploy.sh`, and an `AGENTS.md` mention plus build/vet/test, so a B-number in prose proves nothing about a script existing and many blocks are inline-only; the catalog was invoked as `test -f scripts/check_b*.sh && bash …` under `set -u`, so a typo produced no FAIL and no SKIP and the catalog simply got shorter — seven referenced paths did not exist, one of them a dot-vs-underscore typo that meant a contract never ran at all. Fix the paths and add a gate that every referenced script exists, report SKIP rather than FAIL when a prerequisite is unavailable (a missing dependency is not a failure), and update greps that reference implementation details in the same change that moves the code.

**L-62 — Corrupted counters, a red baseline, and baseline false positives all hide breakage.** Duplicate `run_check` entries for the same block inflate pass/fail totals, backticks inside a `run_check` description were **executed by bash** (TD-15), a contract that pinned a function removed deliberately kept passing, and `go vet ./...` was **red on HEAD**, blocking every gate. Baseline false positives erode trust too: a `DROP INDEX IF EXISTS` flagged as destructive DDL, an accessor rename reported as a bug, hardcoded old bridge addresses, stale migration-version assertions, and several "failures" that were probe-context artifacts (probing the host network namespace instead of the container's, so the DB and public HTTPS looked unreachable while readiness reported the DB fine) — read a gate result as a claim to verify, not a verdict.

**L-63 — Test-quality rules that came out of real misses.** Port a handler's tests **in the same commit** as the handler (the refactor dropped 12 test files and ~600 functions, then spent a 1–2 day tail re-porting 30+), and write the per-feature test harness first and port **one** test file as proof of concept, because re-inventing the harness twice cost 2–3 days. System tests against external systems must restore prior state so they can run on the production VM, `:memory:` SQLite is not coverage for the SQLite code path, and a query's portability is only visible in the other dialect.

**L-64 — Readiness and liveness are different contracts; several "bugs" were correct behaviour.** Liveness is the process and readiness is dependencies with a 1-second cache, so a 503 from a stopped headscale container, or a readiness p99 of ~300 ms under 50 concurrent scrapes because the cache serializes, is expected rather than a DB problem; a `SIGSTOP`ped process answering nothing, a `mv` of the open database file being harmless on Linux (the inode survives while descriptors are open), and lock contention absorbed by the busy timeout are all normal. Sessions are stateless JWTs, so a restart does not log users out — rotating the signing key does. The v0.26.0 fault-tolerance matrix (twelve cases) produced 11 PASS / 1 PARTIAL / 1 documented FAIL: readiness flipped back within 2 s, the session survived a restart, and a restore preserved 5 users and 4028 audit rows, while the FAIL is the subnet-router watchdog (L-56) and the PARTIAL is that the Telegram alert for an offline exit node was never exercised end-to-end; `/etc/hosts`-based partition simulation does **not** work because DNS is cached in-process, so stop the container instead.

## 10. Documentation & process

See also [`README.md`](README.md), [`internals.md`](internals.md).

**L-65 — Refactor process rules from the v0.30 postmortem.** Wrap-and-migrate beats delete-and-rewrite and the no-behaviour-change rule outranks a clean diff, so introduce the per-feature seam satisfied by thin wrappers and never do a 70-file rename. Delete nothing you cannot re-derive — the 4260-line i18n catalog was split mechanically by a script, and the two residual handler tests test rendering that lives in that package, so do not delete them to "finish" — and move least-dependent first while keeping the binary green at **every** commit, running the catalog plus VM smoke at each phase boundary ("catching a regression at a phase boundary is 10x cheaper than after the last phase"). Prove a move lost no behaviour with a coverage diff (before/after profiles, diff empty or renames only) and enforce a file-size budget (300 lines soft, a hard gate near 400; a `_part1`/`_part2` split is naming, not clarity).

**L-66 — Ghost methods, double-registered routes, and stale comments.** A legacy method and its wrapper can coexist with different behaviour (two similarly named global-client accessors) and cleaning up callers took three extra commits, while removing a struct field the old tests used is a silent break damped only because the new harness landed first — so prefer one canonical helper per concern and delete the alternate outright. Moving handlers can double-register routes, and comments that assert a superseded architecture ("as of v1.3.0 skygate is PG-only") actively mislead, so fix the comment in the commit that invalidates it.

**L-67 — Documentation and trackers drift into a second, wrong source of truth.** Live examples: a project doc claimed Go 1.23 while the module file declared 1.25.0, readmes claimed "66/66 checks" while the catalog had 223 check invocations, readmes described the pre-v1.3.0 architecture long after the driver changed, a readme claimed no SSH mount while both the check script and the wiring existed, and one link target had a doubled path segment. The backlog was about a release behind the agent instructions, one workstream was described as blocked, shipped **and** done in three sections, a durability setting was praised in one entry and called a red herring in another in the same file, a UI refactor was "deferred" in one file and DONE in two others, and several blocks were stamped SHIPPED while later entries listed them as pre-existing FAILs. Rules: pin counts and versions with a script (**trust grep over a human count** — the consistency contract found 7 and 11 occurrences where a hand count found 6 and 4), update the tracker in the same commit, never leave two unreconciled statements about one decision, and say so when a claim depends on a script that was never merged.

**L-68 — Historical documents are read-only, corrections go forward, and claims must be re-verified.** Never edit a historical doc in place; add a correction note pointing at the current doc and the superseding commit, because the failure mode is quoting a stale document as authoritative — that produced a wrong root cause (L-32). This digest replaces the removed documents, so when it contradicts current code or [`README.md`](README.md) the code and the current docs win and the correction belongs here; two known-not-current items are that the v0.27.0 "postmortem" was actually a **plan** (its failure modes and RTOs are predictions, never measured) and that the PG cutover is described as blocked, shipped and done in three different documents.

**L-69 — Module boundaries and canonical helpers (never inline these).** Node-name lookups go through the canonical helper, device deletion through one coordinator called by both user and admin handlers (so cleanup, ACL regen, cache invalidation and audit are identical), session decoding through one JWT helper, rule annotation in the handler before grouping, route advertisement through the one client helper that formats the target, and DSN classification through the dialect detector — an inline duplicate of any of these is the bug class the whole-tree sweeps fixed. Alerts must not create an import cycle (each package declares a small local notifier interface and `main` wires the concrete sink), all admin writes go through the single audit helper carrying target type and id, and where a state change and its audit row must not diverge they share one transaction. Modules are opt-in and statically registered with atomic state writes, dynamically loaded modules and a marketplace are out of scope by decision, and feature packages own handler + service + store + types + template + i18n + tests, calling other features only through their **service**.

**L-70 — Security inventory worth keeping current.** An empty JWT secret silently falls back to a logging-only dev default and the "required" check below it is unreachable because the value was already assigned; the settings page writes the env file mode **0644** with the JWT secret and API keys inside and silently **discards** several form fields while the redirect says "Saved!"; the docker socket is mounted into the skygate container, which is a host breakout on RCE; the per-user key-encryption secret is optional so encryption degrades; the Telegram bot token is logged in cleartext because Go substitutes the full URL into a URL error; the SSH target is an injection vector (L-36); and host-key checking is trust-on-first-use without pinning.

## Rejected / abandoned approaches

- **PG-only (SQLite removed)** — v1.3.0 removed SQLite and v1.5.4 restored it; do not delete a working backend to add a second. Also rejected: build tags for dialect selection (one binary serves both), treating SQLite as second-class, and hiding PG-only features in the UI instead of showing an explicit "requires PostgreSQL" message.
- **`lib/pq`**, **one squashed PG schema**, **managed PostgreSQL**, **`pg_auto_failover`** — rejected for the pgx driver, per-version migration diffing, self-hosted Patroni, and the same.
- **Litestream + SQLite as the long-term HA answer** (5–15 min failover versus the < 1 min target, non-zero RPO, a single-file DB that hurts past ~1 GB), **a second replica** (unnecessary at this scale), and **headscale on PostgreSQL now** (blocked, 0.29.x has no PG support).
- **Active-active multi-writer HA** — headscale's API is not built for concurrent writers, so one instance must own the connection and others must queue through a shared work table, and last-write-wins lets a slow write clobber a fast one; the operator chose active-passive with a priority chain, **auto-reclaim off** (manual reclaim only, to prevent flapping), Patroni untouched, Tailscale Funnel skipped.
- **Auto-promotion without an operator** — deferred, because without an external lock both nodes can promote; force promote/demote does not bypass the elector, which writes an intent key the next tick confirms or overwrites, so a promote can log success while the UI still shows the old active node.
- **`DROP`+`CREATE` for DB corruption**; **`synchronous=FULL` plus a single DB connection**; **`envdir` in the archive command** and prefixed object-store env names; **running WAL backups while Patroni manages the data directory**.
- **Tests that assert only dialect classification for a `sqlite:/…` DSN** — insufficient, and exactly why the DSN bug shipped; real opens of all three accepted shapes are required.
- **An in-container reverse proxy on by default in front of an existing terminator** — a rendered config with placeholder hosts made the ACME client refuse it and crash-loop, and when an external terminator already owned 80/443 the container intercepted its traffic and answered an opaque TLS error, so it now sits behind a compose profile and is off by default.
- **`tailscale up` as a generic fix** (a no-op on an authenticated node); **subnet routing as a reachability fix**; **advertising your own LAN, the bridge CIDRs, or a default route**; **an exit node for the Telegram relay**.
- **A dry-run default for a reconciler**; **`INSERT OR IGNORE` for re-attribution**; **blocking a noisy host in the firewall**; and filtering the 404 stream by source port (infeasible under HTTP/2 multiplexing).
- **The "home router" root cause and the re-auth-every-device tailnet-split fix** — both retracted; **keeping the subnet-router on the old host** (breaks after a DNS repoint); and **a manual preference-row insert** (an interim workaround only).
- **A registry image where the registry is blocked, a musl base for a glibc-linked binary, bridge networking for the relay, and a multi-stage build** — all rejected in favour of a local build on a glibc base with host networking. **A restart for cert pickup** — rejected for a reload signal, since a restart costs a DERP blip. **Pushing certs to each node from the admin page** — rejected, because the periodic object-store poll converges both nodes and works when the active node is down. **A certificate's validity dates as the sync trigger** — rejected for an operator-controlled version/hash file.
- **The colon-separated session cookie and the e2e test's mock session header**; **sourcing the update-request or env file as root** (a compromised service must not be able to hand the root applier a shell); **a `setsid` child to perform the restart** (systemd kills the whole cgroup).
- **Capturing a raw database handle instead of the resettable source in long-lived services** — produced a "database is closed" cascade plus a silent login-audit drop on DSN hot-reload.
- **Disabling the netfilter integration entirely for OS-level tailscale installs** — banned, the directory-less mode is required. **Re-provisioning the same subnet CIDR on a new host** — issue a new preauth key and let the sidecar garbage-collect the old node, and prefer disabling a subnet (which preserves the row and preauth progress) over removing it.
- **Keeping the old handler package as re-export shells**, **cross-feature imports of handlers or templates**, and **a single giant i18n catalog** — all rejected, as were the heavy GitHub client library, a migration framework, OS package distribution, unattended auto-update, in-app release-candidate channels, repack tools at the current schema size, a full rewrite of the 48 KB query file (pilot only), and a big-bang error-rendering refactor across all 482 sites.
- **Deferred by decision, not by accident:** full ACL import/merge (import exists as a shape-validated replace), multi-control-plane, OIDC-driven adoption, bulk first-run adoption beyond the explicit claim flow, a subnet-router discovery wizard, Telegram Bot API rate-limit and message-length handling, MTU guidance, auto-rollback when a promoted node cannot start, backup retention/pruning, and a dependency-free amd64 manifest for pre-release tags.

## Open questions

- **OPEN** — Why containerd's overlay filesystem grew to 6.7 GB without garbage collection; the corruption class (L-18) is defended but the growth cause never was. A disk-monitor cron alerting at 75/85/95% is proposed, not scheduled.
- **OPEN** — Backup retention/pruning is unscheduled (the WAL tool defaults to 5 base backups plus all WAL), and object-store backup as a destination plus a periodic auto-verify are pending.
- **OPEN** — Whether any installer-written DSN shape besides the three tested forms is mishandled; ~25 error-swallowing `ADD COLUMN` loops remain in the SQLite chain, hiding real failures even where they are currently harmless.
- **OPEN** — PG↔SQLite round-trip verification on a live host is **pending operator confirmation** (unit tests prove only `:memory:` SQLite); a PG staging host for the cutover phases is not provisioned; the old-primary rejoin script is an unimplemented TODO; and the PG version matrix (14 / 16 / the 18 actually running) was never finalized.
- **OPEN** — HA Tier 1: DNS provider credentials plus ten open questions in the HA execution runbook await operator input, and the mesh between the nodes, the standby bootstrap and a live DR drill are outstanding even though the code side is marked done; whether the second node is the same host as the planned HA standby was never confirmed.
- **OPEN** — HA design questions never answered: RTO tolerance (5–15 min versus < 1 min), automatic versus manual promotion, budget, and connection-pool sizing (never specified anywhere), while the cluster-management API contracts, bootstrap spec and metrics exporter are unchecked or deferred.
- **OPEN** — The unexplained service on the reverse-proxy host (a gunicorn app answering 401 on every path, not part of standard proxy tooling), why a stale node key lives there, how to silence the 404 stream without harming the valid client, and what the valid 200 client on the other port is. Related: the public proxy forwards only the OIDC locations, so the container's tailscaled logs a `/machine/map` deadline-exceeded loop — add `/machine/*` to the proxy, or disable the container's tailscaled.
- **OPEN** — After the infra re-tag, three devices with valid tag ownership and mesh grants were still invisible from the gateway node; the leading unproven hypothesis is proxy handling of the HTTP/2 long-poll plus client caching, deferred with "investigate separately".
- **OPEN** — Legacy nodes on the synthetic tagged-devices user with no live dev-tag are skipped by all four backfill strategies, and a fifth strategy is a proposal only.
- **OPEN** — OIDC duplicate-user creation recurs on every fresh bootstrap and needs a headscale-side mapping fix or manual intervention, while adding an email column to the portal-users table and the email-based claim mapping stay deferred behind it.
- **OPEN** — ACL adoption: full import (converting an existing hand-written policy) is designed but unimplemented and merge mode is deferred until after it, CLI-minted preauth keys match none of the four attribution strategies, and there is no bulk first-run adoption beyond the explicit claim flow.
- **OPEN** — `tailscale status --json` fails inside the skygate container (readiness falls back to a state-file check), suspected to be a bind-mount permission or socket issue and not blocking; MTU guidance for the subnet-router, exit-node and DERP paths exists nowhere in the source documents.
- **OPEN** — DERP certificate-sync rows have no UI form yet, so the admin "Sync now" action is the operator path after rotating credentials.
- **OPEN** — Telegram Bot API message-length limits, rate-limit (429 / retry-after) handling and parse-mode escaping are undocumented in the removed sources, so treat them as unverified; the bot token is also logged in cleartext (L-70).
- **OPEN** — Exit-node SSH reachability is partly infrastructure: live SSH targets were empty (the real hosts and non-standard ports lived only in the operator's SSH config), some nodes' public SSH is filtered, and whether to force route acceptance for unverifiable nodes is undecided.
- **OPEN** — Orphan node-ownership rows for a departed user (including an overflowed id) were deliberately left in place at the operator's instruction, and legacy SQLite data on the migrated host also awaits an archive-or-delete decision.
- **OPEN** — Which install kind should own a host that currently has both a docker and a dead native install; no duplicate-install detection exists, and the CDN rule-grouping documentation contradicts itself (one file says DEFERRED, another says DONE, with the plan never moved out of the current-plans directory).
- **OPEN** — Whether the release pipeline now attaches checksums for real releases (the fix landed with a contract simulation, but a mirror cannot use the API fallback), and whether the current release contains both the SQLite idempotency fixes and the `sqlite:`-prefix fix.
- **OPEN** — ~450 raw-error sites remain against a pinned leaking baseline of 101 in 37 files, with the shared error renderer, a linter rule and a flash-block test named as the next step rather than done; ~50 skipped test files and the dialect-leak guard test are likewise proposed rather than shipped.
- **OPEN** — Documentation follow-ups: a few pages are untranslated or intentionally partial (install details stay English because they mirror Tailscale's UI labels), duplicate `run_check` entries and the silent missing-script pattern need tightening, and one B-number is referenced in prose without a real check script.
