# Устройство потеряло теги после перерегистрации — и перестало попадать в правила

## Симптом

Устройство зарегистрировалось заново (например, после OIDC-входа), в headscale оно
`online`, но **доступ пропал**: на страницах устройства нет привычного тега
`tag:dev-<user>-<device>` (или пропал `tag:private`), а в журнале skygate видно, как
два прохода в одну минуту пишут теги:

```
18:15:08 infra-backfill: AddTag called for node=55 (ensure tag:private)
18:15:10 tag-reconcile: applied "tag:dev-skyadmin-skybars" to node 55 — database said it was
         owned by "skyadmin", headscale had []
```

Итоговый набор тегов на узле — только `tag:dev-skyadmin-skybars`: `tag:private`,
который у узла был до перерегистрации, исчез, и все per-device правила ACL перестали
совпадать с этим устройством.

## Причина

headscale при повторной аутентификации узла **сбрасывает все его теги**, а API тегов
**заменяет набор целиком** — то есть каждая запись тегов это «прочитать текущий набор →
дописать свой тег → записать». Два писателя skygate (`infra-backfill`, который
добавляет `tag:private`, и `tag-reconcile`, который добавляет dev-тег) работают в одном
тике и оба читали набор через **5-секундный кэш** `ListAllNodes`. Второй писатель
записывал набор, прочитанный ДО первого, и затирал его тег.

Исправлено в B477 (v1.5.223):

* запись тега читает набор **без кэша** (`ListAllNodesFresh`) и держит клиентский
  мьютекс `tagMu` на всё время «прочитать → записать»;
* после успешной записи кэш сбрасывается, поэтому панель сразу показывает реальные
  теги, а не состояние до записи;
* `UntagNode` подчиняется тому же правилу (снятие тега — тоже перезапись набора).

## Что делать

1. Обновиться до релиза с B477 (или новее) через `/admin/update`.
2. Проверить теги узла:

```bash
headscale nodes list | grep -i <устройство>
# или
headscale nodes list -o json | jq '.nodes[] | select(.id==<id>) | .tags'
```

3. Если устройство уже потеряло тег на старом билде, вернуть его вручную (после
   обновления автоматика больше не затрёт остальные):

```bash
headscale nodes tag -i <id> -t tag:dev-<user>-<device> -t tag:private --force
```

`headscale nodes tag` заменяет набор — перечисляйте ВСЕ теги, которые должны остаться.

4. Убедиться, что правила снова совпадают: `/admin/devices` (или `/my/devices`) должен
   показывать устройство с ожидаемым тегом, а `journalctl -u skygate | grep tag-reconcile`
   — `applied=<N> failed=0`.

## Как это проверяется в дереве

* `internal/headscale/tags_b477_test.go` — шесть тестов на фейковом headscale:
  второй писатель сохраняет тег первого, существующий неизвестный тег выживает,
  параллельные писатели не теряют друг друга, `UntagNode` не трогает соседние теги,
  запись видна следующему рендеру, отсутствующий в списке узел всё равно
  тегируется.
* `scripts/check_b477_tag_survival.sh` — контракт: мьютекс и свежее чтение в обеих
  мутациях, сброс кэша после записи, отдельная функция `fetchAllNodes` без доступа к
  кэшу, прогон тестов, дискриминатор пре-B477 формы, регистрация в гейте, EN+RU
  документация.
