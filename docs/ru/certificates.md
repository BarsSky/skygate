# Сертификаты — получение, публикация и продление

Skygate умеет три вещи с TLS-сертификатом:

1. **Получить** сертификат у Let's Encrypt по **HTTP-01** прямо из панели
   (`/admin/certificates` → «Получить сертификат у Let's Encrypt»).
2. **Опубликовать** пару — полученную или вставленную оператором PEM-пару — в файлы, которые
   читает `certsync`, в S3 (если настроен) и прокси (если skygate им управляет).
3. **Сообщить** ровно то, что произошло: какой файл записан, какая версия в S3, была ли
   перезагрузка прокси и причина каждого пропущенного шага.

> **Историческая справка (B467, v1.5.214).** До этой версии кнопка «Загрузить» проверяла пару,
> ничего не записывала и говорила «Cert uploaded … certsync scheduler will pull within 30s»:
> колбэк, который она вызывала, не был подключён ни на одной установке. Если вы на более старой
> версии — эта кнопка не работает, используйте пути из таблицы ниже напрямую.

---

## 1. Предусловие для HTTP-01, без обиняков

Let's Encrypt проверяет домен, открывая

```
http://<домен>/.well-known/acme-challenge/<токен>
```

и не пойдёт по редиректу в место, которое не сам выбрал, и не будет использовать нестандартный
порт. **Этот запрос обязан попасть именно в skygate** (`SKYGATE_PORT`, по умолчанию 8080).
Skygate сам отдаёт этот путь, ровно чтобы проверка могла пройти, но маршрутизация — факт о
вашем развёртывании:

| Ваша схема | Что должно быть верно |
|---|---|
| Публичный IP на хосте skygate, на :80 больше ничего | пробросить 80 → порт skygate |
| Спереди обратный прокси (nginx, Caddy, NPM…) | правило для `/.well-known/acme-challenge/` → `http://<host skygate>:8080` и **никакого** редиректа на этом пути |
| :80 уже занят другим сервисом (например DERP) | только правило пути выше, если не переносить этот сервис |

Если запрос попадает не туда, попытка падает на шаге проверки, и панель называет причину
поимённо (домен, путь и токен). При неудаче ничего не публикуется, действующий сертификат
продолжает работать.

### Подстановочные имена

`*.example.com` требует **DNS-01** (TXT-запись), которого эта установка пока не умеет:
`internal/dnsexternal` — заглушка с A-записями без поддержки TXT. Поэтому форма отказывает
подстановочному имени и объясняет причину, вместо того чтобы дать CA отказать позже. Перечислите
имена явно (`skygate.example.com, head.example.com`).

## 2. Порядок действий

1. **Сначала прогон на staging.** Поставьте галочку «Проверочный контур». Сертификат будет
   подписан недоверенным тестовым CA — браузеры будут ругаться, и это цель: так проверяются и
   маршрутизация, и весь заказ, без расхода боевых лимитов (5 одинаковых сертификатов в неделю,
   50 на домен).
2. Введите имена, нажмите «Выпустить сертификат». Одна попытка — один заказ.
3. Прочитайте сообщение: контур CA, файл (`cert.pem`), отпечаток, результат S3 и результат
   перезагрузки. У каждого «нет» есть причина.
4. Когда прогон на staging прошёл, повторите **без** галочки. Боевой сертификат заменит
   тестовый; предыдущая пара останется в `cert.pem.prev` / `key.pem.prev`.
5. Убедитесь, что прокси действительно отдаёт новые файлы (перезагрузка выполняется, если в
   `PATH` есть `caddy` или есть юнит `caddy`; иначе перезагрузите сами).

### Куда пишутся файлы

| Путь | Что это |
|---|---|
| `/var/lib/skygate/certs/cert.pem` | действующий сертификат (лист + цепочка) — его читает `certsync` |
| `/var/lib/skygate/certs/key.pem` | соответствующий приватный ключ, `0600` |
| `/var/lib/skygate/certs/cert.pem.prev`, `key.pem.prev` | заменённая пара (один шаг назад) |
| `/var/lib/skygate/certs/.certsync-version` | кэш версии/SHA, из-за которого `certsync` не перезапишет вашу публикацию |
| `s3://<CertSyncBucket>/certs/{cert.pem,key.pem,.version}` | общая копия, только если настроен бакет |

Каталог переопределяется через `SKYGATE_CERTSYNC_LOCAL_DIR`.

### Откат

```bash
cd /var/lib/skygate/certs
cp cert.pem.prev cert.pem && cp key.pem.prev key.pem   # один шаг назад
caddy reload --config /etc/caddy/Caddyfile 2>/dev/null || systemctl reload caddy
```

Если S3 настроен и вы публиковали, помните: `certsync` сравнивает `.version` на каждом тике, и
откат «только на диске» будет перезаписан более новой копией из S3. Откатывайтесь через форму
загрузки (она публикует новую версию) или отключите `certsync` на время отката.

## 3. Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SKYGATE_ACME_EMAIL` | *(пусто)* | контакт аккаунта; CA предупреждает об истечении сертификата |
| `SKYGATE_ACME_DIRECTORY` | боевой Let's Encrypt | явный URL каталога CA; перекрывает галочку staging |
| `SKYGATE_ACME_ACCOUNT_KEY` | `/var/lib/skygate/acme-account.key` | ключ аккаунта (создаётся при первом обращении, `0600`) — **сделайте бэкап**: потеря означает новый аккаунт CA и его историю лимитов |
| `SKYGATE_CERTSYNC_LOCAL_DIR` | `/var/lib/skygate/certs` | где лежит действующая пара |
| `SKYGATE_CERTSYNC_S3_BUCKET` | *(из `/admin/backup`)* | общий бакет, если у вас больше одного хоста |
| `SKYGATE_READONLY_COPY` | *(не задана)* | на восстановленной копии: она не должна ни получать, ни публиковать (см. `docs/deploy.md`) |

`SKYGATE_ACME_ACCOUNT_KEY` лежит в каталоге данных намеренно: `/tmp` — не место для личности
установки.

## 4. Продление

Сертификат на 90 дней без продления — это запланированный простой, поэтому цикл встроен (B469).
Он продлевает тот сертификат, который **уже отдаётся**: имена берутся из его SAN, то есть
продление может только продолжить выданное и никогда не выдумывает список доменов; и он
использует тот же issuer и тот же публикатор, что и кнопка, поэтому пути не разойдутся.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SKYGATE_ACME_RENEW_ENABLED` | `false` | **включается явно** — фоновый цикл, который ходит к CA с лимитами, запускается только по вашему решению |
| `SKYGATE_ACME_RENEW_BEFORE` | `720h` (30 дней) | окно, в котором продление считается нужным; должно быть меньше срока жизни сертификата |
| `SKYGATE_ACME_RENEW_INTERVAL` | `12h` | как часто пересчитывается решение (и как часто повторяется неудачная попытка) |
| `SKYGATE_ACME_STAGING` | `false` | продление через staging CA (у кнопки своя галочка); staging-сертификат недоверенный — только для отладки |

Что пишет журнал на каждой проверке:

```
acme-renew: enabled (window=720h0m0s, check every 12h0m0s, directory=…, cert=/var/lib/skygate/certs/cert.pem)
acme-renew: no attempt — reason=fresh days_left=44 not_after=… domains=[skygate.example.com]
acme-renew: renewing [skygate.example.com] (reason=due days_left=12 …) via https://…
acme-renew: renewed [skygate.example.com] — written to /var/lib/skygate/certs/cert.pem (s3=false version=0, reloaded=true, took 3.2s)
```

Каждая попытка пишет строку аудита: `certs.renew`, `certs.renew_failed` (CA отказал) или
`certs.renew_publish_failed` (выпущен, но записать пару не удалось). **Восстановленная копия не
продлевает ничего** — `SKYGATE_READONLY_COPY=1` выключает цикл вместе с остальными писателями.

«Почему не продлевается»: проверьте три вещи по порядку — `SKYGATE_ACME_RENEW_ENABLED=true` в env
юнита (и перезапуск после правки), `days_left` в строке `no attempt` (действительно ли внутри
окна?), и есть ли сертификат вообще (если нет, цикл пишет `nothing to renew` и отправляет к кнопке).

**По-прежнему не автоматизировано: DNS-01** (подстановочные имена или хост без доступного :80).
Нужна поддержка TXT в `internal/dnsexternal`, которой нет — поэтому форма и отказывает wildcard.

## 5. Аудит и диагностика

Каждая попытка пишет одну строку в `audit_log`, успешную или нет:

| Действие | Смысл |
|---|---|
| `certsync.upload` | опубликована вставленная оператором пара (в строке путь, S3, версия, перезагрузка) |
| `certs.issue` | заказ ACME прошёл и опубликован (домены, флаг staging, URL аккаунта, время) |
| `certs.issue_failed` | заказ упал на названном шаге (ошибка несёт шаг и путь токена) |
| `certs.issue_unpublished` / `certs.issue_publish_failed` | CA вернул сертификат, но записать не удалось — это дефект, а не заказ |

Строки в журнале:

```
acme: account key …            (при старте: файл аккаунта, каталог CA, контакт)
acme: order … created for …    (один заказ на попытку)
acme: <домен> validated …      (CA открыл проверку)
acme: certificate issued …     (цепочка от CA)
certsync: pair published to …  (локальная запись)
certsync: publish ok — …       (итог: sha, размер, s3, reload)
```
